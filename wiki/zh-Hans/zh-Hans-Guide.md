# GW GUI 用户指南

GW GUI 是一个用于读取、写作、转换、检查和模拟软盘图像的Windows应用程序。 它可以控制 Greaseweazle 硬件,通过其内部引擎与磁盘图像文件合作,并运行保存的仿真机配置.

本指南描述了当前版本应用程序中显示的英语界面. 它被写成可打印用户手册的来源:截图说明了控制,而周围的文本解释了选择什么,为什么选择,以及如何验证结果.

> **重要内容:** 读取磁盘是无损的。 写作,消除,固件更新,以及一些硬件工具可以修改介质或硬件. 点击前先阅读相关程序的警告 ** 执行**.

### 如何使用此指南

如果这是你第一次使用 GW GUI完整 [开始](#getting-started),然后跟随 [读取磁盘](#reading-a-disk)。如果应用程序已经配置,则直接跳转到章节,用于您要执行的操作。 当程序要求您更改驱动器、引擎、配置文件或模拟机器设置时,选项章节可作为参考。

界面名称显示于 **粗体**。文件名称、路径、命令和字面值显示为 `code`。注释解释正常行为;警告显示可能改变磁盘、控制器或存储配置的操作。

## 了解工作流程

GW GUI 从图像文件操作中分离物理磁盘操作 :

| 目标 | 投入 | 产出 | 建议页 |
|---|---|---|---|
| 保存软盘 | 物理磁盘 | 图像文件 | **读取** |
| 重建软盘 | 图像文件 | 物理磁盘 | **写入** |
| 更改图像格式 | 图像文件 | 一个或多个图像文件 | **改划** |
| 检查轨道和异常 | 图像文件 | 视觉分析 | **可视化** |
| 浏览存储在图像中的文件 | 支持的图像/文件系统 | 文件与目录 | **Disk Explorer** |
| 诊断驱动器或控制器 | Greaseweazle 硬件 | 计量或状况 | **工具** |
| 运行保存的虚拟机 | 保存的机器配置 | 模拟会议 | **模拟** |

为了保存,首先进行生擒,并保持作为主人不变. 从主机创建已转换或修复的工作副本 。 这样可以避免重复物理读取,并保存基于部门的格式可能无法保留的信息。

## 开始

### 所需经费

- 带有窗口 Microsoft .NET 应用程序所需的桌面运行时间 。
- A级 Greaseweazle 物理软盘操作控制器。
- 配置路径到 `gw.exe` 当使用时 Greaseweazle Host Tools 发动机。
- 合法获得 ROM 当一个仿真机器需要时,文件。

应用程序检查启动时所需的.NET运行时间。 如果丢失, 请跟随安装提示, 然后重新启动 GW GUI.

### 连接硬件前

运行物理磁盘操作前检查以下内容 :

1. 连接 Greaseweazle 控制器到稳定 USB 端口 。
2. 用正确的方向连接软缆.
3. 在插入有价值的介质之前连接驱动器供电.
4. 确认驱动器大小和密度与磁盘相符 。
5. 可能时写入保护源盘 。

GW GUI 无法防止不正确的电缆、不适当的电源或机械不安全驱动器造成的损坏。 先用消耗性磁盘测试不熟悉的硬件.

### 第一次发射

1. 打开 `gwgui.exe`.
2. 打开 **选项**.
3. 单位 **控制器和驱动器**,扫描控制器并配置驱动器。
4. 校验或选择路径 `gw.exe`.
5. 单位 **发动机**,选择每个操作应该执行哪个引擎。
6. 返回主窗口并选择所需的操作标签 。

### 确认设置准备好了

工作设置应在状态栏中显示控制器和驱动器,例如驱动器的编号、大小、密度和 COM 端口 。 单位 **选项 > 控制器和驱动器 **,控制器应当标记 ** 可用 ** 和驱动器 ** 配置 **运行 ** 主计长信息** 在读取贵重媒体之前,如果您想要在不更改磁盘的情况下验证通信。

### 选择引擎

GW GUI 在一些业务中,可能暴露出不止一个执行。 该 **Greaseweazle Host Tools** 引擎引用配置 `gw.exe`; 内部 GW GUI 引擎处理器支持应用程序内部的操作。 对读、写、转换和 Disk Explorer。如果一个操作被选中的引擎不支持, GW GUI 报告这种情况,而不是自动更改引擎。

## 主窗口

主窗口将主操作分为七个标签:

- **读取** 从物理磁盘创建图像。
- **写入** 将图像写入物理磁盘。
- **改划** 将一个磁盘图像格式转换为一个或多个输出格式。
- **可视化** 显示音轨和通量或解码数据。
- **Disk Explorer** 浏览支持的文件系统和磁盘内容 。
- **工具** 提供硬件维护和诊断指令.
- **模拟** 管理和运行已保存的模拟机器。

底部的控制台显示正在执行的命令及其输出. 状态栏报告选定的驱动器、配置和当前状态。

### 读取接口

大多数操作页面遵循相同的模式:

1. **来源或目的地** 控件表示磁盘、图像或文件夹。
2. **格式控件** 选择自动检测或显式机器和格式。
3. **配置控件** 应用可重复使用的设置。
4. **高级设置** 显示通常可选的参数。
5. **执行** 启动操作。
6. 该 **控制台** 显示生成的命令、进度、警告和错误。

该 **执行** 按钮并不意味着所有值对插入的磁盘都是安全的。 总是在写入或维护操作前审查目的地和选定的驱动器.

### 状态栏和控制台

状态栏左侧识别主动物理驱动. 中心在选择时显示活动配置 。 国家指标报告应用程序是否准备好或繁忙。 控制台不仅仅是诊断:它是发送到选定引擎的命令的权威记录. 需要保存或共享此命令时使用其副本控制 。

## 读取磁盘

打开 **读取** 选项卡,将物理软盘显示为图像。

<p align="center"><img src="../images/main-read-en.png" alt="读取标签" width="78%"></p>

### 基本程序

1. 在配置的驱动器中插入源磁盘 。
2. 选择图像类型 :
   - **原始图像( R)SCP)** 保存通量级信息。
   - **已知磁盘格式** 使用选定的机器和格式创建图像。
3. 选择目的文件夹 。
4. 输入输出文件名 。
5. 如果需要,请选择配置 。
6. 点击 **执行**.

控制台显示准确的指令和进展. 在操作完成之前不要移除磁盘或断开控制器 。

### 选择输出类型

使用 **原始图像( R)SCP)** 当目标为档案捕获,分析,恢复,或后来的转换. 一个原始的图像记录了定时信息和多重革命,这对不寻常的格式,薄弱的部门,保护计划,以及受损的媒体都有用.

使用 **已知磁盘格式** 当您已经知道磁盘家族,需要直接可用的扇区图像时。 这种选择可能较小,更容易在其他软件中打开,但它代表了解码的结果,而不是驱动器观察到的每一个细节.

当不确定时,先创建原始图像. 以后可以不读盘子而转换.

### 文件夹、文件名和配置

该 **文件夹 ** 是目的目录。 该 ** 文件名** 应当识别磁盘,而不只依赖其物理标签。 有用的档案名称包括标题、磁盘编号或侧面,以及适用时的条件说明。 不要添加与选定输出格式相冲突的格式扩展名。

A级 **简介 ** 应用已保存的一组已读参数。 仅在知道其中包含的内容时选择一个 。 该 ** 默认** 剖面图适合于正常的第一次尝试;专门的恢复剖面图可能有意读取更多的革命或不同的轨距,因此需要更长的时间。

### 高级设置

扩展 **高级设置** 访问特定格式或专家参数。 除非磁盘需要特定的音轨范围、革命计数或控制器选项,否则这些值保持不变。

共同的高级价值包括:

| 设置 | 目的 | 什么时候改啊 |
|---|---|---|
| 音轨范围 | 限制圆筒和头部读取 | 单面媒体、不寻常的几何或定向恢复通行证 |
| 革命 | 控制旋转次数 | 不稳定或受保护的轨道增加; 适当时只减少速度 |
| 专家论点 | 通过额外的引擎参数 | 只有在有文件记录的情况下 Greaseweazle 指导 |

### 校验成功读取

不只依赖缺少错误对话框 。 命令完成后 :

1. 确认输出文件存在且不是空的 。
2. 读取失败或缺少音轨的最后控制台行 。
3. 打开图像 **可视化** 以检查双方和预期的轨道范围是否包含数据。
4. 打开它 **Disk Explorer** 当文件系统被支持时。
5. 将操作日志保留在重要的档案记录中。

如果重复读数不同,保留每个原始捕获,而不是覆盖第一个。 在恢复过程中,差异可能是有用的。

## 写入磁盘

打开 **写入** 选项卡,将已有图像写入物理软盘。

<p align="center"><img src="../images/main-write-en.png" alt="写入标签" width="78%"></p>

### 基本程序

1. 插入目标磁盘 。
2. 选择源图像 **浏览**.
3. 确认检测到的格式 。
4. 如果需要,请选择配置 。
5. 点击 **执行**.

写入取代目的地磁盘上的数据. 启动前验证选中的驱动器和图像 。

> **警告:** 写作是破坏性的。 它取代目的地磁盘上的磁性数据. 尽可能使用一个被写入保护的源归档和一个单独的目的地磁盘.

### 写入前

点击前检查四个项目 **执行**:

1. **图像 :** 选择的路径是预定的源图像。
2. **磁盘 :** 驱动器中的磁盘可能被安全覆盖。
3. **驱动器 :** 所配置的大小和密度适合目的介质。
4. **格式 :** 自动检测或手动选择的格式匹配图像。

如果源图像尚未测试, 请打开 **可视化 ** 或 ** Disk Explorer** 先说 成功写入无法修复不完整的源图像 。

### 轨迹检查和修改

选中图像后, **可视化音轨 ** 打开它的轨道代表。 ** 修改** 在写入前先披露支持的图像修改 。 可用的动作取决于选定的格式和引擎.

### 正在验证书面磁盘

当引擎支持验证时,将其用于重要媒体. 否则,将书面磁盘读回新图像,并比较其解码内容或检查其中 **可视化**,将校验抓取与原始图像分开,这样原件就不会被覆盖。

如果在一致的轨道上写入失败, 请检查磁盘条件、 密度、 驱动器清洁度和驱动器配置 。 如果随机发生故障, 请检查 USB 稳定与控制通信。

## 转换磁盘图像

该 **改划** 选项卡将源图像转换为一个或多个目的格式。

<p align="center"><img src="../images/main-conversion-en.png" alt="转换标签" width="78%"></p>

### 基本程序

1. 选择源图像。
2. 可选地提供输出名称 。
3. 选择机器家族.
4. 选择一个或多个输出格式和扩展名。
5. 启用 **添加标签** 如果文件名使用配置的标签模式。
6. 点击 **执行**.

该 **选中 ** 面板列出所要求的产出。 ** 文件迁移** 为迁移所支持的文件提供专用工作流程,而不是进行标准图像转换。

### 选择格式

该 **机器 ** 列表过滤显示的格式 ** 格式** 显示面板。 一个格式名称描述逻辑磁盘布局;扩展描述输出容器. 有些格式可以用一个以上的扩展表示,有些容器不能保留原始来源的每一个特征.

只选择您实际需要的输出 。 多种格式在创建存档主机,仿真器兼容拷贝,和一个操作中另一个分析工具的拷贝时有用.

### 输出命名和标记

**输出名称 ** 允许您控制为选定格式生成的基础名称。 ** 添加标签 ** 应用配置在 ** 选项 > 常规**。标记可以编码家族、格式、扩展、日期或时间。 在转换大批次之前先预览“选项”中的实例,以使文件的命名一致。

### 检查转换结果

对于每项要求的产出:

1. 确认文件已创建 。
2. 检查控制台中无法解码的音轨或扇区 。
3. 打开结果在 **Disk Explorer** 如果其中包含一个支持的文件系统。
4. 将预期磁盘容量和内容与源比较.

转换可以在报告目的地格式所固有的信息损失的同时完成. 即使转换后的图像看起来正确,仍保留原始图像。

## 可视化磁盘图像

该 **可视化** 选项卡显示图像的结构和数据分布。

<p align="center"><img src="../images/main-visualization-en.png" alt="可视化标签" width="78%"></p>

1. 点击 **打开磁盘映像**.
2. 保留 **自动检测** 启用,或手动选择机器和格式。
3. 使用 **链接缩放** 使两侧保持相同的缩放水平。
4. 使用 **重设** 以恢复初始视图。
5. 打开 **检查员** 关于选定区域的详情。

传说区分了正常通量,短和长的过渡,标题,解码数据,并检测出异常. 原始图像可能包含无法解码为已知文件系统,但仍可在此检查的数据.

### 解释观点

每个大型圆形面板代表一个圆盘侧面. 中心识别侧面及其当前数据状态;同心位置对应轨道. 颜色根据传说对检测到的区域进行分类. 可视化器旨在回答诸如:

- 图像包含一边的数据还是两者兼有?
- 是否有预期的音轨?
- 反常现象是孤立的还是整个磁盘重复的?
- 自动检测是否识别出一个可信的机器和格式?

异常颜色是检查区域的理由,而不是磁盘无法使用的证据. 复制保护,非标准格式化,记录薄弱,以及损坏的扇区可以产生不同的结构,需要背景解释.

### 建议的检查顺序

从链接的缩放开始,可以在同一尺度上比较两边。 选择一个可疑区域, 打开 **检查员**,并与相邻的轨道进行比较。 如果结果似乎是一个检测问题,则禁用自动检测并选择已知的机器和格式. 测试后返回自动检测,所以强制设定不会意外用于另一个图像.

## 正在探索磁盘内容

该 **Disk Explorer** 选项卡浏览支持磁盘图像为文件等级。

<p align="center"><img src="../images/main-disk-explorer-en.png" alt="Disk Explorer 选项卡" width="78%"></p>

1. 打开已有图像或读取磁盘。
2. 保留 **自动检测** 启用,除非您需要强制使用机器或格式。
3. 审查量信息:系统、保护、文件系统、容量、空闲空间和项目计数。
4. 浏览左边面板中的目录 。
5. 选择一个在右面板中查看其细节的项目。

如果图像格式或文件系统不支持,请使用 **可视化** 来检查原始结构

### 理解各小组

顶部摘要描述挂载的图像和检测到的音量. 左下方面板包含目录等级. 中央表格列出选定目录中的项目,包括名称、修改日期、类型和大小。 右侧面板显示选定项目的细节 。

Disk Explorer 并不意味着每个原始轨道都被完全解码。 使用卷摘要和项数作为快速的可信度检查,然后在保存准确性时打开代表性文件或者与已知目录列表进行比较.

### 当什么都没有出现时

首先确认图像路径正确. 然后检查检测到的机器和格式. 有效的图像可能包含一个不支持或损坏的文件系统, 在这种情况下, 探索者可以保持空置, 即使 **可视化** 显示记录的数据。 不覆盖或丢弃仅基于空探索器的源图像 。

## 使用工具

该 **工具** 选项卡组 Greaseweazle 维修业务。

<p align="center"><img src="../images/main-tools-en.png" alt="工具标签" width="78%"></p>

从左边的列表中选择一个命令,审查其参数,然后单击 **执行**。只有在验证了选定的控制器和驱动器之后,才可使用破坏或硬件改变命令。

大多数工具对话框包含三个领域:顶部的参数,中央的状态和原始输出区域,以及底部生成的命令. 命令预览会随着选项的启用而改变 。 未选中的参数通常意味着“ 不修改此值, ” 而选中的参数包含命令中的该值 。

个人诊断对话框的描述如下: [硬件诊断和维修](#hardware-diagnostics-and-maintenance).

## 模拟

### 打开保存的机器

该 **模拟 ** 选项卡列表已保存配置。 选择一个并单击 ** 打开**。每个运行的机器都出现在自己的标签中。

<p align="center"><img src="../images/main-emulation-welcome-en.png" alt="模拟欢迎屏幕" width="78%"></p>

在其中创建和编辑机器 **选项 > 模拟 > 配置 ** 和 ** 选项 > 模拟 > Amiga**.

如果没有出现配置, 请先在选项中创建 。 一个保存的配置结合了机器模型,模拟器版本, ROM,内存,视频,音频,存储,和输入映射. 保存配置不启动; 返回主 **模拟 ** 选项卡和单击 ** 打开**.

### 运行机器控制

<p align="center"><img src="../images/main-emulation-running-en.png" alt="运行模拟机器" width="78%"></p>

运行机器工具栏提供功率,暂停,重置,保存状态,负载状态,捕获,以及显示控制. 它还显示:

- 已配置的快速保存和快速装载快捷键;
- 活动渲染器,例如 Direct3D 11;
- 全屏和释放鼠标的快捷键;

<p align="center"><img src="../images/tool-firmware-en.png" alt="固件更新" width="62%"></p>

更新控制器固件 。 **更新卸载器** 明确标注为有风险的,除非正式的固件程序要求,否则应保持残疾状态。 更新时不要断开控制器 。

更新前, 请确认已连接的控制器 **主计长信息**,使用稳定的直线 USB 连接,并关闭其他可以访问它的软件. 完成后,重新连接或重新扫描控制器,并再次读取其信息,以验证所报告的固件版本.

## 日志和操作历史

打开操作历史以通过操作检查保存的日志 。

<p align="center"><img src="../images/operation-history-en.png" alt="行动历史" width="68%"></p>

选择左侧显示其内容的日志。 **导出** 保存用于诊断或支持的副本。 路径和命令行可能包含个人文件夹名称,因此在共享前审查导出日志.

主窗口中的直播控制台显示当前命令和最近的输出. 它的复制按钮复制了显示的文本 。

### 读取日志

一个有用的诊断日志包含生成的命令,时间戳,引擎输出,以及最终状态. 从下方向上的工作:识别最终错误,然后找到第一个警告或之前失败的音轨. 后来的通用失败往往只是早先更具体的信息的后果。

在比较两次尝试时,检查控制器,驱动器,引擎,配置文件,源路径,输出格式和专家参数是否相同. 否则,不同的结果可能反映不同的设置,而不是磁盘不稳定。

## 应用数据和便携式使用

GW GUI 保持用户数据与应用程序二进制分离。 根据所选软件包和模式,设置、日志、下载工具、仿真器组件、捕获、状态和机器配置都存储在应用程序中 `Data` 目录或配置的用户数据位置。

在替换或移动便携式设备之前,请将完整的应用程序文件夹放在一起并备份 `Data` 文件夹。 不移动单个文件 `lib`,因为应用程序从这个结构解决了自己的和第三方的库.

### 建议的备份内容

当对您的工作流程很重要时, 支持以下内容:

- 应用程序设置和配置;
- 控制器和驱动器定义;
- 模拟配置;
- ROM 道路与合法持有 ROM 备份;
- 硬盘和可移动介质图像;
- 抓获和保存状态;
- 用作保存记录的操作日志。

磁盘图像可能比设置大得多 。 尽可能只存储档案主读,并进行复制。

## 建议的工作流程

### 存档未知磁盘

1. 使用适当的维护程序检查和清理驱动器。
2. 如果可能, 请写保护磁盘 。
3. 选择 **读 > 原始图像( R)SCP)**.
4. 使用描述性文件名, 并读取有多个革命的正常音轨范围 。
5. 检查控制台并保存日志 。
6. 检查双方在 **可视化**.
7. 将副本转换为可能的扇区格式。
8. 在 **Disk Explorer** 或合适的软件。
9. 保存生主,木,和注并.

### 从图像重新创建磁盘

1. 检查图像,确认其预期的家庭和形式。
2. 插入一个具有正确尺寸和密度的消耗性或故意可写入的磁盘。
3. 打开 **写入** 并选择图像。
4. 确认已配置的驱动器和检测到的格式 。
5. 写盘子.
6. 读回单独的验证图像.
7. 比较解码内容, 并查看可疑的轨道 。

### 创建模拟 Amiga

1. 打开 **选项 > 模拟 > 配置** 并创建或选择一个机器。
2. 单位 **Amiga > 常规**,选择模型和模拟器版本。
3. 指定一个兼容的、合法获得的 ROM.
4. 保留模式默认值 CPU 和 RAM 在第一个靴子上。
5. 配置带有保守自动设置的视频和音频.
6. 添加存储设备和关联复制的媒体图像 。
7. 审查键盘、鼠标和控制器任务。
8. 保存配置.
9. 返回到 **模拟 ** 并单击 **打开**.
10. 只有在一个成功的基线启动后,一次更改加速或高级设置。

## 安全核对表

在此之前 **读取**:

- 源磁盘在正确的驱动器中;
- 尽可能保护来源;
- 输出路径不会覆盖已有的母版;
- 配置和音轨范围匹配磁盘。

在此之前 **写入 ** 或 ** 擦除**:

- 目标磁盘可能被销毁;
- 图像和驱动器正确;
- 磁盘大小和密度兼容;
- 没有将归档主机用作目的地 。

在硬件更改工具之前 :

- 没有进行其他操作;
- 选择正确的控制器;
- 记录了当前值;
- 控制器有稳定的力量, USB 互联互通;
- 动作由硬件文档支持。

## 解决问题

### 控制器没有列出

1. 将控制器直接连接到计算机上.
2. 打开 **选项 > 控制器和驱动器**.
3. 点击 **扫描**.
4. 验证控制器状态和驱动器配置 。
5. 运行 **主计长信息** 如果检测成功但命令失败。

如果还没出现,再试一次 USB 端口和电缆,然后重新扫描。 检查 Windows 设备管理器是否为新检测到的串行设备 。 一个可见于Windows但缺失的控制器 GW GUI 通常指向繁忙的端口、 stale 配置或主机工具问题; Windows 中缺失的控制器指向 USB动力 驱动器 或硬件

### `gw.exe` 无法找到

打开 **选项 > 控制器和驱动器 **,然后使用 ** 查找 gw.exe **, ** 选择 **,或 ** 下载最新版本**。确认检测到的路径指向 Greaseweazle 安装。

选中后, 运行 **主计长信息** 如果在联系硬件前失败,请检查日志中是否有无效的可执行路径、缺失的文件或无法启动的版本。

### 操作使用错误的引擎

打开 **选项 > 发动机** 并检查分配的引擎 精确操作。 GW GUI 不默不作声地回到另一引擎。

引擎设置是分开的: 更改转换引擎不会改变读、写或 Disk Explorer。保存选项后重新打开失败的操作,并在控制台中确认生成的命令。

### 图像不被识别

只有当您知道正确的机器和格式时,才能禁用自动检测。 否则,试试看 **可视化** 选项卡,以便在较低级别检查图像。

检查来源是原始通量捕获,扇区图像,压缩容器,还是带有误导扩展的无关文件. 绝不只为强制检测而重命名扩展名;转换必须正确解释源结构.

### 模拟没有开始

校验保存的配置, 安装模拟器版本, 选中 ROM,存储路径,以及模型兼容性。 审查应用程序日志以获取完整的错误细节 。

暂时返回 CPU, RAM,视频,并存储到一个简单的模型兼容基线. 如果基线开始, 一次恢复一个自定义设置 。 用另一个仿真器版本或机器定义创建的保存状态,即使干净的靴子起作用,也可能失败.

### 快捷键或输入无效

检查两个全局 **模拟 > 快捷键** 页面和机器专用键盘、鼠标或控制器页面。 解决任何标为冲突的任务。

如果抓取鼠标,请使用运行机器工具栏中显示的释放快捷键. 如果一个控制器在“选项”打开后被连接,在指定它之前再运行控制器检测 。

### 命令意外失败

1. 读取直播控制台输出.
2. 打开 **行动历史** 用于保存完整日志。
3. 确认选定的控制器、驱动器、配置文件、引擎和文件路径。
4. 如果必须共享用于诊断,则导出相关日志。

### 音频裂缝或暂停

增加仿真音频延迟, 关闭 CPU- 密集的应用程序,并返回视频帧跳过和加速到以前的值。 验证是否选中了预定的 Windows 音频设备 。 一次更改一个设置, 这样有效的校正可以识别 。

### 模拟显示为空白或慢

返回分辨率和行模式到 **自动**,禁用帧跳过和闪烁器临时修复,并尝试先前工作的渲染器。 确认配置 ROM 和插入的启动介质是有效的。 该 FPS 指标有助于区分渲染性能问题和没有启动的机器。

### 读取包含不稳定的音轨

重复读到新文件名, 酌情增加革命, 并比较受影响的音轨 。 使用正确的程序清理驱动器头,检查磁盘是否有物理损坏。 不要反复读取明显的剪贴或损坏的媒体,因为进一步通过可能会使其恶化。
