### Vérification des 24 modules — définitions de firmwares et rattachement aux machines

Vérification du code présent au 25 octobre 2026. Les chemins ci-dessous sont relatifs à `src/GWGUI.Emulation.<module>/`. Une inspection de fichier dans Common ne constitue pas à elle seule un catalogue de BIOS par machine. Les chemins d'installation et exigences propres à un cœur restent distincts des identités et compatibilités matérielles. Cette vérification ne prétend pas avoir exécuté tous les BIOS et tous les émulateurs.

| Module | Données et parcours effectivement constatés | État de la séparation machine/émulateur |
| --- | --- | --- |
| Acorn | `Emulators/AcornEmu/Dictionaries/FirmwareDictionary.cs` contient les identités et statuts du Model A ; `Factories/AcornEmuMachineFactory.cs` appelle son inspecteur sans transmettre le modèle. B2 annonce un firmware intégré dans `Emulators/B2/Functions/SettingsFunctions.cs` et hérite d'un scan externe vide. | À corriger : données BBC encore locales à AcornEmu, portée Model A implicite ; pas de définition commune de ces BIOS réutilisée par B2. |
| Amstrad | `Common/Machines/Common/Dictionaries/FirmwareCatalog.cs` calcule les empreintes et retourne `IsKnown: false`, `CompatibleModels: []`. | Apple | `Common/Machines/Common/Functions/FirmwareFunctions.Scan.cs` valide la sélection ; MiniVmac reconnaît le MD5 et la taille dans `Emulators/MiniVmac/Functions/FirmwareFunctions.cs`, avec les constantes du cœur. | Epoch | `Common/Machines/Common/Functions/FirmwareFunctions.cs` détermine les modèles Super Cassette Vision concernés et vérifie l'empreinte commune. La fabrique interop transmet le modèle. | Rôle et reconnaissance partagés dans Common/Machines. |

| Fairchild | `Common/Machines/Common/Functions/FirmwareFunctions.cs` consulte `FirmwareConstants.Md5(model, role)` pour les BIOS 1 et 2 ; la fabrique interop transmet le modèle. | Reconnaissance et rôles communs par machine constatés. |
| Mattel | `Common/Machines/Common/Functions/FirmwareFunctions.cs` identifie Executive/Graphics par taille et MD5 des constantes communes. La fabrique transmet modèle et cœur. | Données de reconnaissance partagées ; le parcours conserve aussi les contraintes du cœur sélectionné. |
| Microsoft | `Common/Machines/Common/Dictionaries/FirmwareCatalog.cs` retourne des identités inconnues et aucun modèle compatible. `Common/Dictionaries/EmulatorCatalog.cs` découvre les fabriques de l'assembly ; aucun dossier Emulators ni fabrique concrète n'est présent dans ce projet inspecté. | Inspecteur générique ; pas de catalogue BIOS matériel ni de raccordement à un backend concret démontré. |
| NEC | `Common/Machines/Common/Dictionaries/FirmwareCatalog.cs` reconnaît les System Cards PC Engine et les BIOS PC-FX avec leurs modèles. | Nintendo | `Common/Machines/Common/Dictionaries/FirmwareCatalog.cs` retourne `IsKnown: false`, `CompatibleModels: []`. `Functions/FirmwareConfigurationFunctions.cs` inspecte selon `adapter.GetFirmwareSlots(configuration)`. Les listes de BIOS sont déclarées dans `Emulators/<cœur>/Constants/FirmwareConstants.cs`, par exemple Gambatte. | Rôles principalement décrits par cœur, sans catalogue commun de versions matériel démontré. |

| Philips | `Common/Machines/Common/Functions/FirmwareFunctions.cs` définit des rôles ; `Emulators/Common/Interop/Functions/FirmwareFunctions.Identification.cs` reconnaît Videopac/CD-i à partir de `Emulators/Common/Interop/Constants/MediaRuntimeConstants.cs` et tient compte du cœur. | Reconnaissance matérielle située dans l'interop des émulateurs ; pas entièrement séparée dans Common/Machines. |
| Sega | `Common/Machines/Common/Dictionaries/FirmwareCatalog.cs` possède une table d'empreintes avec modèles et régions. Les backends déclarent séparément leurs emplacements dans `Emulators/<cœur>/Constants/FirmwareConstants.cs` ; l'inspection de configuration utilise leurs slots. | Mixte : identités matérielles communes existantes, emplacements et exigences encore répartis dans les backends. |
| Sharp | `Common/Machines/Common/Functions/FirmwareFunctions.cs` définit rôles, tailles et empreintes X68000/X1 selon le modèle. Les fonctions runtime des backends préparent les noms de fichiers natifs. | Reconnaissance matérielle commune constatée ; chargement natif distinct. |
| Sinclair | `Common/Machines/Common/Functions/FirmwareFunctions.cs` définit les banques Pentagon/Scorpion selon le modèle et leurs tailles. | SNK | `Common/Machines/Common/Functions/FirmwareFunctions.cs` demande les slots à l'adaptateur. `Emulators/NeoCd/Functions/FirmwareRuntimeFunctions.cs` contient les signatures et familles Front/Top/CDZ ; d'autres backends fournissent leur propre inspection. | Reconnaissance matérielle encore répartie par émulateur, Common servant de relais. |
| Sony | `Common/Machines/Common/Dictionaries/FirmwareCatalog.cs` retourne un firmware inconnu sans modèles compatibles. Les slots sont définis par cœur, par exemple `Emulators/Pcsx2/Constants/FirmwareConstants.cs`. | Le fichier nommé catalogue ne fournit pas les identités BIOS communes aux machines ; besoins et inspection restent liés aux backends. |
| Thomson | `Emulators/Theodore/Factories/TheodoreMachineFactory.cs` retourne une liste vide pour le scan externe. | Aucun catalogue matériel de firmwares externes raccordé dans ce parcours ; cela ne prouve pas une panne du firmware fourni par le cœur. |
| Watara | `Emulators/Potator/Factories/PotatorMachineFactory.cs` retourne une liste vide pour le scan externe. | Aucun firmware externe déclaré dans ce parcours ; aucune ROM BIOS supplémentaire n'est à inventer. |
| Wenquxing | `Emulators/Wqxemu/Dictionaries/FirmwareCatalog.cs` définit les fichiers par modèle ; `Functions/FirmwareRuntimeFunctions.cs` définit les tailles et validation. Common demande ces exigences à l'adaptateur. Le catalogue matériel commun décrit CPU/RAM, pas ces firmwares. | Définition matérielle des firmwares encore locale à Wqxemu. |

Conclusion de vérification : la répartition n'est pas uniforme. Des bases matérielles communes existent déjà ; ailleurs, Common relaie les backends ou possède seulement un inspecteur générique. La correction Acorn doit réutiliser cette distinction et ne pas attribuer globalement au cœur AcornEmu les compatibilités du Model A. Cette inspection n'a modifié aucun autre module ni leur fonctionnement.
