## Premiers éléments recoupés

Sources primaires : https://docs.libretro.com/library/applewin/, https://docs.libretro.com/library/minivmac/, https://github.com/libretro/libretro-core-info, https://github.com/libretro/libretro-minivmac. AppleWin Windows original : https://github.com/AppleWin/AppleWin ; le port Libretro doit être identifié dans les sources de build, sans confondre les deux exécutables.

Le fichier info Mini vMac actuel identifie une variante Mac II et exige MacII.ROM (MD5 66223be1497460f1e60885eeb35e03cc). Les modèles 128K/512K/Plus/Classic de la liste doivent donc être comparés aux configurations réellement compilées avant proposition à l'exécution. Aucun support de ces modèles n'est encore affirmé.

AppleWin annonce démarrage sans contenu, chemins complets, états sérialisés et contrôle des disques. Relever le comportement réel et les options dans les sources et le paquet Windows ; ne pas transformer les options natives de touches ordinaires en second éditeur clavier.

Relevé initial produit dans artifacts/apple-source/native-contracts.json : deux DLL x64 et SHA-256 contrôlés, sources fixées par révision. AppleWin propose bien les familles demandées ; Mini vMac source compile un Macintosh II avec 8 MiB, 68020 et FPU. La cadence native source Mini vMac est 60 Hz, différente de la documentation ; sizeof(info->path) ne déréférence pas info. Le chargement AppleWin sans contenu a été vérifié dans son processus isolé, avec rendu et états. Le firmware Macintosh absent déclenche une erreur contrôlée et la fermeture de son hôte ; le démarrage Macintosh avec ROM réelle reste non validé.

Caractéristiques matérielles recoupées : Apple, fiches Macintosh 128K https://support.apple.com/en-hk/112190, 512K https://support.apple.com/en-hk/112187, Plus https://support.apple.com/en-hk/112183, Classic https://support.apple.com/en-ca/112195 et II https://support.apple.com/en-ca/112188. Fréquence Apple II dérivée de la formule NTSC dans Common.h de la révision AppleWin relevée ; RAM matérielle de base distincte de la RAM imposée par la compilation native. Macintosh II matériel de base 1 MiB ; Mini vMac compilé 8 MiB. Les entrées Macintosh non prises en charge restent dans le catalogue matériel, hors catalogue exécutable.

Sonde binaire terminée sans Initialize/LoadGame : AppleWin 1.32.0.0, 29 options ; Mini vMac b36, 2 options. Installation commune, factories et runtime isolé implémentés ; compilation complète et essais natifs réalisés. Écart d'identité observé dans le Debug existant : SDK de l'application 0.3.0.0, référence du module Acorn 1.0.0.0. L’AssemblyVersion SDK est stabilisée à 1.0.0.0 ; le chargement de l’hôte natif et le runtime Apple ont été vérifiés.

## Images livrées provisoires — à revoir

Les huit photographies restantes ont été détourées par masques polygonaux sans génération de matériel. Grand côté : 512 pixels. Les inscriptions originales sont conservées. À revoir : précision et franges des contours, espaces entre périphériques, câbles omis et faible résolution de la source J-Plus (200 × 164 pixels agrandie). Ces limites visuelles sont acceptées provisoirement pour poursuivre le travail selon la demande utilisateur. Le J-Plus livré utilise la vue complète Macgeek ; sa provenance et ses droits non identifiés restent signalés dans la source ci-dessus.

Contrôle complet : 20 contrôles Apple réussis, aucun échec ni contrôle ignoré. Dix PNG transparents contrôlés, grand côté au plus 512 pixels ; les huit nouveaux assets mesurent exactement 512 pixels sur leur grand côté. Nettoyage des sources et résultats temporaires différé : le contrôle automatique refuse la suppression des dossiers contenant les photographies et leurs crédits sans autorisation explicite. Ces dossiers restent hors des fichiers de livraison et du commit.

Build final terminé avec succès : application et dix modules (acorn, amstrad, apple, atari, commodore, microsoft, nec, nintendo, sega, sony). Exécutable et dix DLL contrôlés après la fin du script. SDK livré : identité 1.0.0.0. Chemin de test : build/Debug/GW GUI/gwgui.exe.
